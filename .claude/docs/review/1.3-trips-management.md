## 3. Fix scope cho `plan-task`

Mọi endpoint `@RoleRequired(UserRole.ADMIN)` ở class + method. Lỗi: `ResourceNotFoundException` → 404,
`ConflictException` → 409, `IllegalArgumentException` / `@Valid` → 400. Response là DTO, không entity.
Các mục ghi "(D<n>)" làm theo quyết định đã chốt ở mục 6 (user 2026-10-05: **mọi D theo đề xuất A**).

### BE (`manage-revenue-ticket`)

**S1 — `GET /api/trip`** (thay `GET /api/trip/scheduled`)
- Query: `status` (tuỳ chọn, enum `TripStatus`, sai → 400), `routeId`, `busId`, `driverId` (tuỳ chọn),
  `from`, `to` (tuỳ chọn, ISO `LocalDateTime`; lọc `departureTime >= from AND departureTime < to`; `from >= to` → 400),
  `page` (0), `size` (10, tối đa 100 qua `PageRequests`). Sắp xếp `departureTime ASC, id ASC`.
- Response 200: `BaseResponseDto<PageResponse<TripResponse>>`, message đúng nghĩa ("Get Successfully").
- `TripResponse{id, status, departureTime, arrivalTime, route{id, routeName, startPoint, endPoint, distanceKm},
  bus{id, plateNumber, capacity, status}, driver{id, email, fullName}, bookedSeats, revenue, createdAt, updatedAt}`
  — `bookedSeats` = vé `status_ticket <> 'CANCELLED'`; `revenue` = tổng `price` vé `SUCCESS` (D6 = A); `fullName` từ `profiles` (null nếu chưa có).
- Repository: JPQL fetch-join route/bus/driver + `countQuery`; `bookedSeats` (và revenue) lấy bằng
  **1 query `GROUP BY trip_id`** cho các id trong trang (không N+1). Profile tài xế cũng 1 query theo danh sách id.
- Xoá `findTripBusRouteInfo`, `TripBusRouteInfo` (B30: luôn rỗng, typo `geTenPoint`), `getTripScheduled`.

**S2 — `GET /api/trip/{tripId}`** → 200 `TripResponse`; không có → 404; id không phải số → 400.

**S3 — `POST /api/trip`**
- Body `TripRequest` + `@Valid`: `routeId`, `busId`, `driverId` `@NotNull`; `departureTime`, `arrivalTime` `@NotNull`;
  `arrivalTime > departureTime` → 400; `departureTime` ở quá khứ → 400 (D5 = A). **Không nhận `status`, `revenue`**
  (server đặt `SCHEDULED`, revenue D6 = A).
- Kiểm: tuyến tồn tại + `ACTIVE` (không → 409); xe tồn tại, không `MAINTENANCE` (409); tài xế tồn tại, `role=DRIVER`
  (400), `isActive=true` (409, B34 e); **trùng giờ** (S8) → 409. Bỏ chặn theo `IN_USE`/`driverStatus` (D1 = A).
- `@Transactional`; 201 + `TripResponse`.

**S4 — `PUT /api/trip/{tripId}`**
- `tripId` kiểu `Long` (sai → 400). Chỉ sửa chuyến `SCHEDULED` (khác → 409). Body như S3 (đủ field, `@Valid`),
  không đổi `status` (dùng S5).
- Đổi xe: xe mới `capacity` < `bookedSeats` → 409; cập nhật trạng thái xe cũ/mới theo S7. Đổi tài xế: tương tự.
- Chạy lại check trùng giờ (S8), loại trừ chính chuyến này. `@Transactional`; 200 + `TripResponse`.

**S5 — `PATCH /api/trip/{tripId}/status`**
- Body `{status}` `@NotNull`. Chuyển hợp lệ: `SCHEDULED→ONGOING`, `ONGOING→COMPLETED`, `SCHEDULED→CANCELLED`
  (plan §1.3); khác → 409 (cùng trạng thái → 200 idempotent). Không ràng buộc giờ (D4 = A).
- `CANCELLED`: mọi vé chưa huỷ (`PENDING`, `SUCCESS`) → `CANCELLED` trong cùng transaction (D3 = A); hoàn tiền / báo khách để 2.4.
- `COMPLETED`/`CANCELLED`: trả xe + tài xế theo S7. 200 + `TripResponse`.

**S6 — `DELETE /api/trip/{tripId}`** (plan §1.3: chỉ xoá khi chưa có vé)
- Có bất kỳ vé nào (kể cả đã huỷ) hoặc dòng `revenues` → 409 "Chuyến đã có vé, hãy huỷ chuyến". Không có → xoá
  cứng, trả xe/tài xế theo S7; flush, `DataIntegrityViolationException` → 409 (đua với đặt vé, như 1.1 L11).
- 200 `data:null`.

**S7 — Trạng thái xe / tài xế theo chuyến** (B30, D1 = A)
- `Buses.status` = `IN_USE` khi xe có ≥1 chuyến `SCHEDULED/ONGOING`, về `AVAILABLE` khi không còn
  (không đụng xe `MAINTENANCE`); `driverStatus` = `ACTIVE` / `PENDING` tương tự. Tính lại sau tạo, sửa (xe/tài
  xế cũ + mới), đổi trạng thái, xoá — 1 hàm `refreshResourceStatus(busId, driverId)` trong transaction.
- `BusService.update`: chặn đặt `MAINTENANCE` khi xe còn chuyến chưa kết thúc (D8 = A, 409); `RouteService.updateRoute`:
  chặn `INACTIVE` khi tuyến còn chuyến chưa kết thúc (D8 = A, 409) — hiện đổi được (`RouteService.java:57-61`).

**S8 — Check trùng giờ**
- Xe và tài xế không được có chuyến khác `SCHEDULED/ONGOING` chồng giờ:
  `other.departure < this.arrival AND coalesce(other.arrival, other.departure) > this.departure` (plan §1.3).
  `TripRepository.existsOverlapForBus/Driver(id, dep, arr, excludeTripId)` → 409 nêu chuyến bị trùng.
- Chống race 2 admin tạo cùng lúc: khoá row xe + tài xế (`PESSIMISTIC_WRITE`) trước khi check, như 1.2 L2.
